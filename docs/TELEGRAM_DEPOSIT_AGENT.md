# وكيل إيداع Telegram للأرشيف القانوني الخاص

## الغرض

تعمل قناة Telegram المحددة بوصفها **صندوق إيداع** فقط: تضع د. رباب الملفات أو الصور فيها، ويقرأ وكيل الإيداع المرفقات الجديدة عبر جلسة حساب Telegram مخوّلة، ثم يحفظها في الأرشيف الخاص ويصنفها ويعالجها. لا يحتاج هذا التصميم إلى بوت، ولا يمنح الوكيل صلاحية النشر أو حذف الرسائل أو تعديل القناة.

> **حدود الثقة:** الملف المودع في Telegram محفوظ كما وصل، لكنه ليس مصدرًا قانونيًا نهائيًا بذاته. لا يصبح حكمًا أو تعميمًا أو قرارًا قابلاً للبحث إلا بعد التحقق من جهة الإصدار والمصدر الرسمي والعنوان والمرجع ونطاق الصفحات.

## ما الذي ينفذه الوكيل

1. يراقب المنشورات الجديدة في القناة بعد آخر رقم منشور نجح في فحصه.
2. ينزّل المرفق نفسه عبر جلسة حساب Telegram المصرح بها فقط، ثم يحفظه دون تعديل في `originals/telegram-deposit/`.
3. يسجل اسم الملف المنشور، رابط المنشور، وقت النشر، وصف المنشور، الروابط الواردة فيه، الحجم، نوع الملف، وSHA-256.
4. يقرأ PDF النصي؛ ويقرأ الصور عبر OCR عربي/إنجليزي عند توفر محرك OCR. ملفات Word والملفات التي لا يمكن تحويلها بأمان تحفظ وتوضع للمراجعة بدل اختراع حدود صفحات.
5. يميّز مبدئيًا بين الحكم والصك والتعميم والقرار والمبدأ والسابقة والمدونة/الفهرس. المدونة والفهرس لا يعدان حكمًا أو سابقة مستقلة.
6. لا ينشئ PDF مستقلًا إلا عندما تثبت صفحة بداية بمرجع ونوع موثقين داخل PDF. عندها ينتج PDF مشتقًا يحتوي فقط صفحات الوثيقة، مع SHA-256 ونطاق الصفحات والأصل المرتبط.
7. يطابق أولاً البصمة ثم بصمة النص؛ ويحفظ الأصل دائمًا. حالات التطابق تسجل في مراجعة التكرار ولا تصبح قابلة للبحث.
8. يكتب جميع النتائج في فهارس مراجعة خاصة، بحالات `not_eligible`. لا يكتب إلى قاعدة منصة RABAB LEGAL AI ولا يفعل بحثًا أو تنزيلًا عامًا.

## الملفات التشغيلية

| الملف | الوظيفة |
|---|---|
| `scripts/pull_telegram_deposit.py` | جلب مرفقات Telegram الجديدة في جلسة الحساب المصرح بها وحفظ الأصل وسجل الاستلام. |
| `scripts/process_telegram_deposit.py` | قراءة الأصول المحفوظة وتصنيفها وفصل PDF حين تثبت الحدود، إلى مسار مراجعة خاص. |
| `scripts/validate_telegram_deposit.py` | فحص NDJSON والمعرفات والملفات والبصمات ونطاقات الصفحات وحواجز الخصوصية. |
| `scripts/run_telegram_deposit_worker.sh` | دورة العامل الدائم: قفل منع التزامن، مزامنة آمنة، ثلاث محاولات محدودة، معالجة، تحقق، وتسجيل نتيجة جودة منظمة. |
| `manifests/collector/telegram-deposit-file-register.csv` | سجل الأصول الواردة وبصماتها. |
| `indices/collector/pending-telegram-deposit-documents.ndjson` | فهرس الوثائق الخاص قيد المراجعة فقط. |
| `manifests/collector/telegram-deposit-duplicates.csv` | سجل التكرارات المؤكدة بالنص. |
| `manifests/collector/telegram-deposit-binary-duplicates.csv` | سجل مطابقات SHA-256 للأصول المستلمة مع الاحتفاظ بكل نسخة واردة. |
| `manifests/collector/telegram-deposit-failures.csv` | سجل فشل تنزيل محدد قابل لإعادة المحاولة. |

## الإعداد الأولي المطلوب من مالكة الحساب

لا يمكن بدء تنزيل مرفقات قناة Telegram بحساب شخصي دون تصريح الحساب نفسه. الخطوة الوحيدة المطلوبة من د. رباب هي إنشاء تطبيق Telegram شخصي من [بوابة تطوير Telegram الرسمية](https://my.telegram.org/apps)، ثم إدخال القيم التالية في ملف بيئة **خارج Git** وعلى الجهاز المشغل فقط:

```bash
export TELEGRAM_API_ID='...'
export TELEGRAM_API_HASH='...'
export TELEGRAM_PHONE='+966...'
```

لا تحفظ هذه القيم في المستودع أو في تقرير أو في رسالة قناة. بعد ذلك يجرى تفويض تفاعلي لمرة واحدة:

```bash
python3 scripts/pull_telegram_deposit.py --authorize
```

تظهر رسالة إدخال رمز تسجيل الدخول في الطرفية. يدخل الرمز فقط في الطرفية المشغلة. ينشئ البرنامج ملف الجلسة تحت `work/telegram-deposit/`، وهو مسار مستبعد من Git. إذا كان التحقق بخطوتين مفعلاً، تطلب الطرفية كلمة المرور في أثناء التفويض.

## دورة تشغيل آمنة

بعد التفويض، يثبت الوكيل المؤشر على آخر منشور موجود **من دون تنزيل التاريخ السابق**. بهذه الخطوة تصبح كل الإيداعات اللاحقة فقط ضمن دورة الأرشفة:

```bash
python3 scripts/pull_telegram_deposit.py --bootstrap-latest --apply --channel robiai33
```

بعدها تشغّل الدورة من الجهاز الدائم الذي يحمل الجلسة نفسها:

```bash
python3 scripts/pull_telegram_deposit.py --apply --channel robiai33
python3 scripts/process_telegram_deposit.py --apply
python3 scripts/validate_telegram_deposit.py
```

تشغّل عملية المراقبة المستمرة كل 15 دقيقة في العامل الدائم. يستمر المؤشر من آخر منشور فُحص، وتبقى المرفقات الفاشلة في قائمة إعادة المحاولة. لا يعاد تنزيل ملف محفوظ إذا كان زوج رقم المنشور والبصمة مسجلاً. يحتوي العامل على قفل يمنع تشغيل دورتين معًا، وثلاث محاولات متدرجة لفشل النقل العابر، وحالة منظمة محفوظة لآخر دورة وآخر نجاح. تضبط البيئة حد عدد المنشورات وحد حجم كل ملف والميزانية الإجمالية للملفات الجديدة في الدورة، حتى لا يعطل ملف كبير أو دفعة ضخمة بقية العمل. لا يؤدي فشل Git أو Git LFS العابر إلى حذف أصل تم حفظه أو إعادة كتابته.

لا يسحب الوكيل تاريخ القناة دفعة واحدة في أول تشغيل. إذا تقرر استيراد جزء تاريخي، يحدد رقم منشور بداية صريح ويُشغّل بنطاق محدود، مثل `--from-post-id 1300 --limit 25`، ثم يتحقق من الدفعة قبل الانتقال إلى دفعة أخرى.

## تفسير العدد الظاهر في الباحثة

يوصى بعرض أربعة أرقام منفصلة في الباحثة المستقلة، وليس رقمًا إجماليًا مضللاً:

| العداد | المعنى |
|---|---|
| الملفات المستلمة | الأصول المحفوظة من Telegram مع بصمة SHA-256. |
| الوثائق المفصولة قيد المراجعة | PDF أو صور ذات حدود مقروءة، لكنها لم تتحقق من مصدر رسمي. |
| الوثائق المتحققة | وثائق استكملت المصدر والنوع والعنوان والمرجع والصفحات بعد مراجعة بشرية. |
| المتاح للبحث | مجموعة فرعية مصرح بتفعيلها صراحة؛ تبقى صفرًا افتراضيًا. |

تحديث العداد لا يغيّر حالة الوثيقة. لا ينبغي أن تظهر نتائج بحث "حكم براءة في مخدرات" من مدونة كاملة أو ملف Telegram غير متحقق؛ تظهر فقط ملفات أحكام مستقلة ذات نطاق صفحات وبيانات موثقة بعد تفعيلها صراحة.

## الاستمرارية وجودة المخرجات

تعمل الأرشفة الخاصة تلقائيًا بالكامل بعد التفويض: تنزيل الأصل، SHA-256، تسجيل بيانات الاستلام، OCR للصور عند توفره، استخراج النص، فصل PDF عند ثبوت الحدود، التصنيف، ومطابقة التكرار. لا يلزم تدخل بشري لهذه الخطوات العادية. وتصدر كل دورة نتيجة قابلة للفحص تشمل حالة الجلب، وعدد الأصول الجديدة، وعدد المستندات المفصولة، وسجل الأخطاء المؤقتة، ونتيجة التحقق من الملفات وNDJSON وحواجز الخصوصية.

أما إظهار وثيقة للعميل فهو بوابة جودة مستقلة، لا توقف الأرشفة. لا يفعّل العامل الوثيقة للبحث عندما يكون مصدرها الرسمي غير مثبت أو نوعها أو عنوانها أو مرجعها أو صفحاتها غير مكتملة. في هذه الحالة تبقى الوثيقة مؤرشفة ومفصولة في فهرس مراجعة خاص، ويواصل العامل استقبال الملفات التالية بلا انقطاع. يجوز تصميم مرحلة اعتماد تلقائي لاحقة فقط لسجلات تستوفي جميع أدلة المصدر الرسمي والبيانات الإلزامية؛ لكنها لا تعد جزءًا من عامل الإيداع ولا تفعل بحث العميل تلقائيًا.

## حالات تتطلب تدخلاً يدويًا

- الصورة غير مقروءة، أو لم يتوفر OCR عربي، أو كان PDF ممسوحًا بلا نص.
- الملف Word أو صيغة لا يمكن تحويلها إلى صفحات PDF بصورة محفوظة.
- لا يوجد مصدر رسمي مثبت في وصف المنشور أو داخل الوثيقة.
- المرجع أو المحكمة أو العنوان أو حد الصفحة غير مؤكد.
- تطابق رقم مرجع أو نص مع سجل آخر دون دليل كافٍ على أنه الوثيقة ذاتها.
- طلب تفعيل البحث أو التنزيل أو مشاركة نتائج مع منصة المحامية الرقمية.

## الحماية والخصوصية

- لا تُنشأ مفاتيح Telegram ولا ملفات الجلسة ولا كلمات المرور داخل Git.
- لا يسمح للوكيل بإرسال أو تعديل أو حذف محتوى Telegram.
- الأصل لا يعدّل؛ الملفات المفصولة تحفظ في مسار مختلف وتربط ببصمة الأصل.
- لا تدمج تغييرات الأرشفة في `main` دون توجيه صريح.
- لا تكشف مسارات التخزين أو الملفات الأصلية أو سجلات المراجعة في واجهة عامة.
